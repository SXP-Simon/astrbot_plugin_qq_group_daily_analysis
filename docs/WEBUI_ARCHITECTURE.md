# WebUI 架构与设计规范 (WebUI Architecture Specification)

本文档阐述 `astrbot_plugin_qq_group_daily_analysis` 插件内嵌 WebUI 控制台（`dashboard/`）的整体架构设计、分层约束、组件化解耦准则与实现标准。

---

## 1. 架构理念 (Core Philosophy)

控制台前端全面拥抱 **Feature-Sliced Design (FSD)**、**Atomic Design (原子设计)** 与 **MVVM (Model-View-ViewModel)** 架构，追求高内聚、低耦合、强类型、极致可维护性与高信息密度体验。

## 2. 分层规范与职责 (Layer Responsibilities)

### 2.1 `shared/`（基础共享层）
* 包含与业务完全解耦的通用基建：
  * **原子 UI (Atoms)**：`StatusTag.tsx`、`MetricCard.tsx` 等通用展示组件。
  * **通信桥梁 (Bridge)**：`bridge.ts` 负责与 AstrBot 宿主面板安全通信与事件监听。
  * **工具库 (Lib)**：`formatters.ts`（时间/Token/数字格式化）、`useTheme.ts`（明暗模式响应）。

### 2.2 `entities/`（领域实体层）
* 按领域划分独立切片（`task`, `trace`, `group`, `metric`, `report`, `config`, `log`）。
* 每个实体切片包含三个标准子层：
  1. `model/types.ts`：纯 TypeScript 领域模型与枚举定义。
  2. `api/`：强类型的轻量数据获取客户端。
  3. `ui/`：该实体专属的**原子与分子组件 (Atoms & Molecules)**，并通过 `ui/index.ts` 统一导出。

#### 实体 UI 解耦与防膨胀约束（Atomic UI Guidelines）
* **严禁单文件巨石组件**：单个 UI 组件文件原则上控制在 200 行以内，严禁将所有子逻辑内联堆砌在单一主组件中。
* **以 `entities/trace/ui` 为标准范例**：
  * `SpanTimeline.tsx`（阶段树、选中阶段证据与运行中计时，窄容器改为单列）。
  * `SpanHeader.tsx`（阶段标题、耗时参考提示、耗时比例与折叠入口；比例不表示任务进度）。
  * `SpanAlerts.tsx`（阶段执行异常、子任务错误列表与无产出提示横幅）。
  * `LlmAttemptsTable.tsx`（大模型调用与降级重试表格，负责 Provider 去重与错误展示）。
  * `RenderAttemptsTable.tsx`（图片渲染降级策略表格）。
  * `StageMetricsBadges.tsx`（各阶段专属指标药丸徽章）。
  * `PromptsInspector.tsx`（结构化 Prompt 与产物检视卡片）。
  * `SpanPayloadViewer.tsx`（底层数据快照与诊断信息）。

### 数据管理中的增量批次

数据页分区使用共享 Tabs；「增量分析批次 (KV)」简写为「增量分析批次」，「阶段产物快照 (Checkpoints)」简写为「阶段产物快照」，原有入口和跨页字体、素材管理请求保持不变。增量列表、游标、详情和批量删除使用共享控件；文件编辑、字体管理和分区抽屉均使用共享控件；各分区继续由独立 ViewModel 管理读取和修改。

`usePluginDataViewModel` 管理群聊、批次及详情请求。切群先清空旧内容，以请求编号拒绝迟到响应；同群刷新失败保留上次结果。详情关闭、切换及卸载使旧请求失效。删除和重置确认固定目标并防止重复提交，错误保留在弹窗中；批量操作继续使用逐项 revision 校验，单项失败不掩盖其他结果。

真实增量接口和 Mock 均返回秒级游标时间、群聊及去重数量；`last_message_timestamp` 来自批次内实际消息时间，不能用批次生成时间代替。原 `timestamp` 字段继续保留。批次详情保留话题、金句、质量评价、完整 JSON 和复制入口；未知扩展数据仍能查看，缺失消耗与实际零值分别展示。

阶段快照由 `useCheckpointsViewModel` 独立管理查询和操作状态，由数据页 ViewModel 组合；视图不发请求。查询使用显式字段更新，传入 `undefined` 表示清空条件，避免默认参数重新带回旧筛选。切换筛选回到第一页，换页保留跨页选择，换筛选清空选择；同条件刷新失败保留已读数据。列表、群聊选项与详情分别隔离请求，关闭或卸载使迟到结果失效。删除确认绑定群聊、日期、阶段及任务，期间发生新查询时不回查旧范围。

快照的「查询」按钮已由筛选项即时查询替代，原页码跳转、刷新、产物 JSON、管理及批量删除继续保留。详情区使用共享 Dialog，复制依赖共享剪贴板降级逻辑，失败不会提前提示成功；未关联任务的按天快照明确标注。仓储列表计数与记录共享一次读事务，排序追加快照主键；任意页码仍采用 OFFSET，跨请求新增或删除不等同于固定快照。Mock 使用同一任务的不同阶段构成多页数据，日期、阶段和任务筛选、单项删除均更新同一份示例存储。

### 2.3 `features/`（功能切片层）
`view-config-backups` 使用共享 Dialog、分页和原生折叠树，只读展示任意旧配置结构；不根据当前 Schema 丢弃未知键。ViewModel 管理列表与详情请求序号、分页和选择，关闭、刷新及卸载使旧响应失效，返回文件名不匹配时不展示内容。长文本保留换行，损坏项显式提示，关闭恢复入口焦点。

* 承载由用户主动发起的独立交互行为或业务操作：
  * `trigger-task/`：发起群分析表单，保留群聊、平台、模型与模板选择。`useTriggerTask` 管理选项加载、唯一匹配补全和提交锁，失败通过 Promise 回到表单内显示；成功通知使用共享 Toaster，后台刷新失败不冒充提交失败。关闭或重开后，旧选项请求不写回新表单。
  * `filter-traces/`：Trace 列表的多维度复合筛选栏。
  * `cancel-task/`：二次确认中止运行中任务。
  * `resume-task/`：断点续跑与失败阶段重试。
  * `rerender-report/`：复用保存的分析结果换模板重绘。ViewModel 管理格式与模板能力、提交锁及请求生命周期；视图使用共享弹窗和表单控件。切换报告、关闭或卸载后废弃旧请求，重绘失败保留选择，列表刷新失败不冒充生成失败。
  * `filter-logs/`：日志级别与关键词流式过滤。

### 2.4 `widgets/`（复合微件层）
* 将多个实体和功能有机组合为自包含的业务组件（Organisms）：
  * `ActiveTaskBoard.tsx`：活跃任务看板与实时步进计时器。
  * `TraceDrawer.tsx`：保留调用接口的任务诊断窗口，使用 shadcn Dialog 组织 Summary、SpanTimeline、TraceLogViewer；宽屏并排显示阶段树与记录，窄屏改为单列。
  * `AnalysisTimelinePicker.tsx`：按时间倒序的任务选择条，直接显示平台、状态与记录的消耗和耗时。支持原生触屏滑动、鼠标拖动与方向键、Home / End；鼠标纵向滚轮在列表可移动时转为横向滚动，到达首尾后放行页面滚动，横向手势与缩放保持原生行为。仅选中项进入 Tab 顺序，切换取消旧滚动帧，尊重减少动态效果，不滚动整页或虚构缺失指标。
  * `OverviewTrendCharts.tsx`：分析次数、Token 消耗和服务商分布，使用共享范围选择器与原生明细表。`useOverviewTrends` 管理范围、校验响应及隔离迟到请求；旧图保留自身范围标识，零消耗不借用历史总量。图表配置独立于请求状态，沿用 ECharts、主题变量与纯文本提示。服务商占比使用环形图及 HTML 图例，超过七个渠道时保留前六名并聚合其他；全部明细保留原始渠道，零消耗不绘制等分扇区。
  * `TokenChartWidget.tsx`：按模块比较记录的 Token 总数，保留输入、输出和零消耗明细。可仅接收概要总数，缺少明细不补零；模块合计不一致时展示原始记录与说明，不编造其他模块。ECharts 采用主题变量和纯文本提示，表格支持键盘访问。
  * `FieldRenderer.tsx` & `TemplateListRenderer.tsx`：动态配置表单渲染器（支持 Provider/Persona 自动点选与模板列表）。模板列表通过 `useTemplateListModel` 处理默认值、字段编辑和排序，保留未知字段；视图使用共享按钮和弹窗，删除确认绑定原条目，配置变化后不删除错位条目。T2I 测试、字体和素材管理继续复用各自功能模块。

### 2.5 `pages/`（页面与视图模型层）
配置的 `useConfigViewModel` 隔离读取请求并在卸载后废弃回执；保存采用同步提交锁和版本号，保存期间的新编辑不会被旧提交覆盖。模型、人格选项失败独立提示，重新读取失败保留草稿并禁止未经加载的保存。持久化结果和后续页面刷新结果分别反馈，字段错误计数从校验结果派生；定位错误前清除搜索并尊重减少动态效果设置。

`ConfigPage` 保留动态字段渲染器，用共享按钮与确认弹窗组织保存、重新读取；宽屏展示可键盘操作的分组导航，窄屏使用原生分组选择器。分组与字段搜索均支持名称、说明和顶层键名，匹配分组时展示该组可见字段；搜索临时切换展示，不改写原分组选择。读取期间禁用表单，保存期间允许继续编辑；重新读取有草稿时先确认。

报告列表由 `useReportsViewModel` 管理分页、搜索防抖、错误与旧响应隔离，视图组合 `ReportFilterBar`、`ReportList` 和原重绘、预览弹窗。群号、文件名、任务编号、日期与时间升降序统一在服务端查询全部历史；原「本页开始／结束日期」「本页时间排序」改为「开始／结束日期」「时间排序」。后端对同一批查询结果核验文件，再计算总数和分页；确定缺失且未重新登记的索引才清理，目录离线时保留索引。页数减少时请求最后一页；查询失败保留已读页并注明来源。

报告操作由 `useReportActions` 管理，预览按请求序号隔离，关闭或卸载后忽略迟到响应；返回内容需与请求文件名一致。同文件下载期间持有提交锁，HTML 临时地址延后释放并在卸载时清理，失败展示在页面及对应预览中。图像与 HTML 继续通过原报告 API 和宿主通信层读取。

统计页由 `useContextInsightViewModel` 管理筛选防抖、选择与详情生命周期；列表、群聊和详情分别处理错误，切换任务立即隔离旧明细，手动刷新强制读取详情。缺失的 Token 明细不补零，上下文概要只补充已记录字段；`ContextFunnelWidget` 区分缺失、零值及不一致数量，留存比例不表示执行进度。时间列表每次加载 50 条，通过开始时间与任务编号游标继续读取更早记录，合并时按编号去重。首次查询总数只代表该次读取；追加请求、筛选与刷新按请求代次隔离，失败保留已经读到的记录。主动刷新后若选中项不在加载范围，显示提示而不自动改选第一条；更改筛选条件才重置选择。查看详情使用现有诊断入口。

* 全面实施 **MVVM 模式**：
  * **ViewModel (`use*ViewModel.ts`)**：负责状态机管理、远程接口轮询、防抖搜索、数据衍生计算与错误处理。
  * **View (`*Page.tsx`)**：纯 JSX 声明式视图，仅接收 ViewModel 输出的属性与回调函数，严禁在 View 内部直接编写异步网络请求或复杂状态衍生逻辑。

### 2.6 `app/`（应用根层）

日志页使用共享筛选控件与原生可选文本区域，保留 Ctrl+A / Command+A 区域内全选及关联任务入口；清空全部缓冲需确认，复制与操作反馈由 ViewModel 管理。`useLogsViewModel` 校验实时事件，去重并合并查询期间到达的日志；慢查询期间不叠加轮询。暂停、隐藏或卸载使旧响应与订阅回调失效，清空期间阻止重复提交，失败保留已有记录。页面不因新日志强制滚动，可主动返回最新位置。条目总数表示筛选匹配数量，不称为全局缓冲总数。

功能分类目录由日志 API 返回，前端按用途分组，未知分类仍可在「其他」中选择。后端优先按调用模块分类，正文关键词作为兜底；筛选与 SSE 使用同一个分类键。日志页与任务日志共用实体层的中文标签，未知键原样显示，文件位置和复制原文不翻译。

分析记录的 `useTracesViewModel` 使用实体查询契约管理筛选、分页和排序，不依赖组件库的表格事件类型。搜索防抖 250 毫秒；条件变化立即废弃旧请求，加载失败保留已有记录并提示。记录减少导致页码越界时重取最后一页，手动刷新保留当前条件；任务终态 SSE 只标记历史页面有更新，不强制跳页、重新排序或改选任务，切回页面仍保留浏览位置。总览继续实时处理任务，详情缓存仍按终态事件失效。`TraceFilterBar` 也供统计页复用，日期以本地日的起止时间查询，未填写完整和非法范围不会发送伪造时间。正式 Mock 接口同步处理这些条件和分页排序。

* `AppShell` 使用 `shared/ui` 的 shadcn 标签页和按钮组织导航；`usePageNavigation` 管理已访问页面和滚动恢复。页面保留挂载以保存编辑值，日志 ViewModel 通过激活状态停止隐藏页订阅和轮询。
* `useTheme` 接收 AstrBot 主题通知并同步根节点的 `dark` 类，正文和 Portal 弹层共用 CSS 变量。迟到的初始化结果不能覆盖新通知；Mock 不发送固定亮色通知。
* 导航文字不参与整页 View Transition 快照。内容进入使用短暂过渡，减少动态效果设置关闭动画；键盘操作和焦点行为由基础控件维护。
* 新组件使用 shadcn/ui 和 Tailwind CSS，基础组件源码放在 `shared/ui`，底层 Radix 交互不直接散布到业务页面。迁移中的旧页面暂时保留 Ant Design 主题适配，完成组件替换后移除。
* `subscribeSSE` 对宿主异步返回的订阅编号保留清理标记：页面已离开时立即注销迟到的编号；清理后不再转发消息或错误，重复清理不重复注销。订阅被拒绝时交给调用方的错误回调处理。

任务详情的 `useTraceDetail` 管理详情与日志加载。运行中每轮请求完成后再延迟 1.5 秒更新，终态、关闭或卸载时停止；切换任务及手动刷新使旧响应失效。手动刷新绕过终态缓存，部分请求失败保留已取得的记录并单独提示。ViewModel 不用当前时间补写缺失的任务总耗时。API 层只缓存明确终态，采用最多 100 条的 LRU；SSE 失效同时废弃在途缓存写入资格，较旧请求也不能覆盖或清除较新缓存。

`useTraceDrawerViewModel` 组合详情读取与 `useTraceActions`，后者管理产物预览、下载和续跑请求，隔离关闭或切换后的迟到结果。续跑成功后按回执任务编号读取新记录，同编号回执则强制刷新。`ResumeTaskModal` 使用 `useResumeOptions` 加载并校验模型、模板选项，失败保留编辑值并在弹窗内反馈。详情视图不直接调用 API。

总览按运行任务、近期问题、统计与趋势排列。`useOverviewViewModel` 独立保留三个接口的结果与错误；活跃任务事件经结构校验，事件修订号阻止旧快照覆盖新阶段，有限终态集合阻止迟到进度恢复已结束任务。中止回执以布尔值返回确认弹窗，失败保持可重试；计时仅用于有效开始时间，激活状态控制后台更新。关注区明确限定最近 20 条记录，不把缺少心跳广播直接认定为任务卡死。

WebUI 手动触发的分析可通过「总览 → 正在执行中的分析任务 → 中止」取消。确认后按任务编号调用 `tasks/cancel`，明确显示请求是否成功；成功表示取消请求已接受，后台仍需完成资源回收。看板同时处理 `task_finished`、`task_canceled`、`task_timed_out`，移除对应任务并刷新指标，在途旧响应不得重新插入任务。Mock 中触发、活跃列表和中止后的历史终态也保持一致。

## 3. 任务与链路生命周期状态模型 (Status & Lifecycle Contract)

前端对任务与 Span 的状态判定严格遵循以下契约，禁止模糊掩盖：

| 状态标识 | 语义 | 视觉规范 | 业务判定标准 |
| :--- | :--- | :--- | :--- |
| `running` | 运行中 | 蓝色胶囊 / 旋转指示器 | 任务/阶段正在执行中，秒级步进更新耗时。 |
| `succeeded` | 完全成功 | 绿色胶囊 / 勾选图标 | 所有已开启的子任务均成功产出，且报告正常分发。 |
| `warning` / `partial_success` | 部分成功 / 警告 | 琥珀橙色胶囊 / 感叹号 | 至少 1 个子任务成功并允许发送报告，但存在部分子任务失败或重试耗尽。 |
| `failed` / `error` | 执行失败 / 中断 | 红色胶囊 / 叉号图标 | 开启的 LLM 模块全部失败导致任务熔断中断，或发生未捕获致命异常。 |
| `aborted` | 已中止 | 灰色胶囊 | 用户手动点击中止或系统重载取消。 |

阶段详情保留父子关联，并优先展开当前执行或异常步骤的祖先。`spanTiming.ts` 统一耗时语义：真实零耗时与缺失记录区分；已结束且缺失耗时的阶段不会按当前时间继续增长。仅在任务和阶段均运行中、开始时间有效时显示“已运行”。顶层比例以任务总耗时为分母，子阶段以父阶段为分母；未知或无效分母不显示比例，并行阶段不累加、父子不重复累计。`skipped` 显示为已跳过，无法识别的状态显示为未记录，不推断为成功。

若不存在正在执行或最终失败的阶段，默认定位有失败轮次的渲染阶段。只有失败之后的最后一轮明确成功时才标记“后续渲染已成功”，不改变任务与父阶段的最终状态。窄容器限制阶段列表高度，用户选择后将焦点和滚动定位到证据标题；返回操作恢复选中阶段的焦点，后台轮询不会自动抢焦点。阶段指标使用实体内的 `StageMetric` 与响应式网格，字体、资源和 Typst 遥测字段保持可访问。

`traceMetrics.ts` 为耗时、宿主 RSS、传输体积图提供明确的采样模型。图表只使用已记录耗时，精简视图移除前序重试的整棵子树，完整视图保留全部尝试；不把阶段求和当作任务耗时或重试损耗。RSS 缺测保留空点，不与 Typst 子进程峰值混合。图表沿用 ECharts，主题色读取公共 CSS 变量，Tooltip 使用文字渲染，并提供可展开的数据表。

`promptRecords.ts` 在实体边界逐字段校验提示词记录，保留旧字符串格式、初始与校正文本，以及每一条已记录的重试。未保存正文的调用只展示实际元数据，不从其他轮次补齐或推断校验成功；模块汇总 Token 不挪作初始请求用量。`PromptsInspector` 用选择器与可复制文本组织内容，原始阶段 JSON 保留所有字段，作为结构化视图之外的完整核对入口。

## 6. 数据管理文件边界

存储管理页面只做特征组合：`ManagedFilesPanel` 组合无网络请求的 `StorageOverview` 与 `ManagedPartitionDrawer`，`usePartitionManager` 负责分区选择和页面导航。通用文件查询、选择、上传及编辑属于 `features/manage-stored-files`；字体管理属于 `features/manage-typst-fonts`；自定义模板管理属于 `features/install-template`。特征不得反向导入 pages，上传读取由 ViewModel 调用共享文件读取器完成，弹窗继续保留抽屉内的父子上下文。

分区说明、筛选和跳转目标集中声明于 `entities/plugin-data/model/partitionPresentation.ts`。新增沿用文件管理能力的分区只需增加能力数据；专用业务视图在页面的管理器映射中组合，不把字体、模板和头像操作堆入通用文件列表。

Typst 方案通过 `FontManagementContext` 声明打开字体管理的意图，携带当前模板、CDN 和来源；`App` 执行跨页切换，`usePartitionManager` 在分区加载完成后消费请求并打开同一字体抽屉，特征不导入页面。字体变更通过版本通知重新读取状态，配置 ViewModel 及未保存草稿保留。手动获取链接由后端字体清单生成，按字体上传时由 ViewModel 映射为预设文件名；下载队列先核对缺失项，只对具备不同 Raw 来源的 CDN 文件自动重试一次。

`plugin-data/partitions` 返回插件专属分区的实际路径、文件数、字节数和操作能力。文件列表支持分页搜索；内容接口仅按分区内相对路径读取，单文件上限 32 MiB。创建不覆盖同名文件；替换、重命名和删除必须携带读取时的 SHA256 修订号，冲突返回 409。

模板源码可创建和编辑，字体及固定清单内的素材支持上传替换；报告、备份和派生缓存只支持查看、下载及单项删除。字体仍从插件 data/typst/fonts 加载，资源优先使用 data/typst/resources。数据库、内部状态和编译任务目录不提供直接写入。宿主全局 io_temp_img_* 没有插件归属，不能通过本插件清理。头像缓存通过 DiskCache API 清理，不删除仍在使用的数据库文件。

数据管理保留“存储空间概览”入口，将原先六项“清空”操作改为按分区进入文件列表。可搜索相对路径，预览图片及隔离 HTML，下载原件，逐项删除，维护模板源码及上传字体/素材。字体与素材分区的“按模板下载”复用配置中心组件；自定义模板分区可直接安装完整模板包。覆盖、重命名和删除在详情中进行，必须先读取原文件。


### 业务存档与多选管理

“数据管理 → 分析存档与头像”展示当前插件作用域内的分析历史 KV 及平台头像缓存键。业务 KV 位于宿主共享存储，不重复计入插件文件目录占用。增量批次和快照保留原有结构化详情，另提供“管理”入口以导出完整 JSON、修订或删除。历史和批次允许导入为新记录；阶段快照由分析任务创建，修订只更新产物，不能改变身份、创建时间或有效期。头像缓存仅支持查询、预览、导出及删除后按需重取。

`plugin-data/records`、`records/detail`、`records/mutate` 使用对应仓储和插件 KV 接口，不直接改写 SQLite 文件。业务修订通过 JSON 内容版本拒绝覆盖，且与 daily / incremental / final 群任务互斥。删除最新历史版本会修复每日索引；导入缺失版本会补齐每日索引。单条导入上限 4 MiB。

文件列表的 `extensions` 参数按扩展名先筛选再分页，支持逗号分隔的 JPG / PNG 组合。`files/delete-many` 只接受显式选择的相对路径和列表修订号，每批最多 200 个，逐项返回成功与失败，不使用模糊路径或递归清空。管理页切换筛选条件会清空已有选择，避免误删隐藏项；可独立筛选 HTML、JPG、PNG、Typst（.typ）、SVG、JSON 和字体类型。业务存档、头像、增量和快照列表也提供多选删除，并保留失败项供检查。

存储概览使用共享按钮及语义表格，保留文件占用、分区数、字体素材容量、完整目录和能力入口。首次读取或首次失败不以零容量替代未知数据；刷新失败保留上次分区，概览请求按序号隔离。分区表格提供可聚焦的横向滚动区，数据页 Tabs 及容器设置最小宽度约束，避免宽表将页面撑出窄屏。非零但不足 1% 的占用显示为 `< 1%`，其条长仍按实际比例计算。

存档与头像列表使用共享输入框、按钮和分页器，记录类型入口由“分析历史 (KV) / 头像缓存条目”简化为“分析历史 / 头像缓存”；“查看 / 管理”和“预览 / 管理”对应新版“查看与管理”和“预览与管理”。搜索草稿提交后才查询，清空立即生效。每页仍为 20 条，与后端契约保持一致；翻页保留选择，类型或已提交搜索条件变化时清空选择及管理弹窗，批量删除期间禁用筛选和翻页。ViewModel 统一保存查询条件，迟到的刷新回调也读取当前条件；切换查询清除旧行，同条件刷新失败保留列表，删除导致页码越界时重新读取最后一页。后端仍按记录键倒序分页，不把键顺序冒充创建时间顺序。Mock 存档及头像均包含多页示例，列表只提供元数据，头像详情按需读取。

记录管理弹窗使用共享 Dialog / Button，JSON 查看与编辑保留完整未知字段，仍由实体 API 执行带 revision 的更新。ViewModel 对读取和修改使用同一条目生命周期序号，修改另设同步锁；关闭、切换条目或重新读取后，旧结果不能更新当前内容、清除新请求的忙碌状态或触发新窗口关闭。读取错误可重试，修改失败保留编辑稿。删除需要确认当前 locator，导出始终包含 locator、data、revision；头像保留图片下载、缓存键复制和放大预览。嵌套头像预览的 Esc 只关闭预览，并返回原入口焦点。批次、历史、快照的后端业务校验和副作用保持不变。

弹层保留触发关系的 React 父子结构：分区抽屉内渲染详情、上传和模板安装/卸载弹窗，详情内再渲染源码编辑、重命名和图片放大窗口。文件详情与编辑已使用共享 Dialog；分区抽屉和子窗口共用 Radix Dialog 的层级与焦点管理，Esc 只关闭当前最上层窗口，子窗口关闭后返回原入口焦点。共享弹窗层级统一管理，页面不另行覆盖 z-index。HTML 文件在空 sandbox 的 iframe 内预览，源码通过只读文本框查看；图片与下载使用临时 Blob URL，关闭后释放。

文件修改仍携带读取时的 revision，冲突或其他失败原因直接显示在操作窗口，编辑稿与删除目标保留。同步操作锁阻止连续点击重复写入；关闭或切换分区后旧读取和修改结果不得覆盖新窗口或释放新操作的锁。替换文件尚未读完时禁止保存，取消编辑及重新选择文件会使旧读取失效。单文件 32 MiB 限制、分区权限、相对路径和模板目录前缀保持不变。

减少动态效果模式直接禁用 CSS transition-property，不给原本没有过渡的元素强加短过渡。浮层定位会先测量临时位置，强制非零 transition-duration 会干扰这一过程；需在真实浏览器中检查下拉框与弹层，而非只依赖 JSDOM。

Typst 字体分区使用独立的依赖与安装管理视图。按模板展示已安装/缺失字体及共享关系，提供补齐、上传、替换、移除与格式搜索，不再通过通用二进制详情下载字体。替换保持文件名并提示字体族与依赖影响，移除使用列表版本且刷新缺失状态；字体文件内容只在用户上传时读取。

字体上传先提交少量元数据，再通过宿主二进制接口每次传输 1 MiB，避免整份字体变成 Base64 JSON。进度使用服务器实际保存字节数；取消通过独立 UUID 停止当前请求、清理暂存并拒绝迟到分块。只有完整到达并通过现有格式与修订号检查后才发布正式文件。上传结束与列表刷新使用独立状态，刷新慢不会继续锁住上传操作；当前宿主缺少二进制接口时会明确提示升级。

模板素材通过 `ResourceManagementContext` 从 Typst 方案直达数据管理，保留所选主题与 CDN，返回后保留配置草稿。素材分区原“主题素材状态”页签改为“主题素材管理”：先选择主题，展开清单后可逐文件上传或替换，自动使用清单路径并查询现有本地文件修订号。另一页签“本地素材与替换”继续提供预览、筛选和多选管理；开发仓库中就绪的素材不代表已有 data 本地副本。

Typst 编译详情区分栅格导出的墙钟时间与隔离进程实际消耗的 CPU 时间，并在能读取到常见 Linux cgroup 配额时显示容器 CPU 配额。CPU 时间包含原生线程累计，不能直接等同墙钟；配额也不代表实时可用 CPU，仍可能受上级配额、cpuset、主机竞争或 I/O 影响。未知配额不显示，不推断为无限制；中断编译不伪造未完成阶段的 CPU 耗时。
存储分区按用途显示能力标签、空状态和直接可见的文件类型快捷筛选。自定义模板优先提供 `Typst 模板（.typ）`，历史报告提供 HTML 与图片格式筛选；切换分区会重置条件及选择项。无法在浏览器预览的二进制文件直接下载，不再打开无实际内容的详情框。

自定义模板通过可搜索的选择器按真实顶层目录管理，不将模板卡片全量平铺。下拉列表限制可见高度并虚拟滚动，可搜索名称、目录和说明；页面只展示所选模板的能力、完整目录统计及文件。切换模板清空文件筛选和多选项，安装后直接选中新模板；新增、上传及重命名默认保留当前包前缀。安装模板、手动模板和未完成目录都可整组移除，确认内容明确整个目录及隐藏文件也会移除。内置模板、非法路径、链接目标仍不可移除，根目录零散文件只能逐项管理。`files` 的 `groups` 是分页与搜索前的完整目录统计，`directory` 在分页前精确限定模板，`.` 表示分区根目录文件。

头像缓存分区直接进入平台缓存条目管理，不展示无法操作的数据库文件列表。详情提供头像预览、图片下载与按键清理，图片不再包装成 JSON 导出；批量清理提示也只描述头像按需重取的影响。

原始素材分区默认打开“主题素材状态”，可展开每个主题的文件清单并复制路径、查看缺失和按主题补齐；“本地素材与替换”仅展示插件 data 中的文件。配置备份复用版本及内容查看器，保留原件下载与多选删除。状态分区提供执行任务、分析存档、增量批次与阶段快照入口，旧版历史分区也可直达当前存档。所有跨页入口在跳转前关闭分区抽屉；列表失败在抽屉内提示，不与概览请求互相清除错误。派生图片与画廊预览按可重建缓存说明和清理。

配置参考素材按需读取当前已保存配置，展示图片引用字段及可复制的 `files/…` 路径，同名替换保留引用，重命名或删除提示其影响。引用检查不解析自定义模板源码，不把“未找到配置引用”当作无依赖保证。新增图片从配置中心的具体字段上传以保持目录归属，文件管理只维护已有图片。mock 的配置备份与文件分区共享同一份数据，删除后两处列表同步。

模板安装说明同时覆盖 Typst 与 HTML 入口。mock 的在线及 ZIP 安装返回正式安装契约并创建演示模板包，能力列表、文件分组及卸载操作同步变更；模拟安装不访问网络或解压用户文件。

### 历史查询的一致性与边界

分析记录所有排序追加任务编号，报告时间排序追加文件名，避免相同排序值的不确定次序。分析记录的计数和列表放在同一 SQLite 读取事务中；报告总数与列表来自同一次元数据查询及文件核验结果。文件系统与数据库不能组成原子快照，核验后文件仍可能被移除，预览／下载继续报告实际错误。

统计时间列表采用 `(started_at, trace_id)` 游标；游标之前新增记录、删除锚点不会推移下一批边界，但筛选条件涉及状态时，状态变化仍可能改变成员资格，需要主动刷新。分析表与报告保留任意页码的 OFFSET 分页，每次翻页读取当时的数据，不提供跨请求冻结快照；外部插入、删除以及耗时、Tokens 变化仍可能导致跨页漂移。更新提示减少浏览中断，不等于消除漂移。

时间、群聊与时间联合索引包含唯一排序键，替换原有同前缀索引。`tests/test_trace_pagination.py` 使用一万条临时记录检查查询计划，并覆盖同值排序、插入删除和读取竞争。模糊搜索仍可能扫描，派生指标排序仍可能使用临时排序；不为所有字段盲目增加索引。报告为准确剔除失效文件，每次核验所有匹配路径，成本随匹配数量增加；只检查元数据，不下载或读取报告正文，旧目录补录不因空筛选反复递归扫描。

### 增量批次的数据契约与分页

增量话题使用 `SummaryTopic` 序列化字段 `topic/detail/contributors/contributor_ids`，金句使用 `content/sender/reason/user_id`；不将其他分析场景的热度字段当作增量指标。前后端回归共用由 `IncrementalBatch.to_dict()` 生成的 JSON 样本。

增量列表请求 `page/page_size`（默认 20，最多 100）。仓储一次读取轻量索引，以时间和批次 ID 倒序排序、计算总数并修正越界页码，再读取当前页内容。跨页保留选择，切群清除；迟到的旧页响应不能覆盖新页。分页按每次请求的当前索引计算，不是跨请求冻结快照；并发新增或删除后可刷新重新查看。索引中的批次内容缺失时返回错误，不伪造零值记录。

新保存的批次在索引中记录最后消息时间；旧索引缺少该字段时总览显示“未记录”，不为补算指标读取全部批次。平台筛选与群聊归属另行对齐，不据裸群号推断平台。


### 历史平台与群聊筛选

分析记录、统计和报告通过 `fetchGroupSessions` 获取历史平台与群聊组合，复用实体层 `GroupFilters`。选项以平台标识和群号共同定位，显示群名与群号；平台标识原样传给 API，不把适配器实例名猜成平台类型。切换平台清空群聊并返回首页，选择群聊同时固定其平台，未记录平台与全部平台分别处理。

Trace 查询在计数和分页前过滤平台。报告从产物关联的任务读取平台与群名，不使用同号群最近记录替代；没有关联任务的旧产物保留未知平台。增量存储通过 `IIncrementalStore.for_session(group_id, platform_id)` 绑定 AstrBot 平台实例；批次、时间游标、同秒消息 ID 及清理操作使用同一会话范围。


阶段快照的平台与群名从同一数据库中关联的 Trace 读取，以任务 ID 和群号共同匹配；按天旧快照、关联任务已删除及独立快照数据库均保留未知身份。平台条件在计数与分页前生效，列表仍共用读取事务。`data/checkpoints/groups` 保留原群号列表并提供 `sessions`，页面复用 `GroupFilters` 展示群名与编号。平台变化清空跨页选择并重置页码；页码修正保留平台条件。


### 分区文件列表

`ManagedFileList` 使用共享表单、按钮、分页和 Dialog；`ManagedFileTable` 负责文件行与配置引用，`ManagedFileDeleteDialog` 展示固定文件及修订号的确认范围。视图继续调用 `useManagedFiles`，不直接发业务请求。模板上传和新建源码保留包目录前缀，配置参考素材仍从配置中心新增；上传输入在读取后复位，允许重新选择同一文件。批量选择保留其他页，最多 200 项。

删除请求失败保留确认窗口和明确原因，部分失败在列表汇总；切换分区或目录后不使用旧确认范围。文件数量减少导致页码越界时自动回查有效页。旧筛选的刷新闭包不能发起旧范围查询，列表响应继续受请求序号保护。外层分区抽屉使用同一 Dialog 的侧边布局；固定标题内提供唯一关闭入口，正文采用普通文档流，避免 Grid 约束导致 sticky 标题随长内容滚出。素材下载与本地文件页签改用共享 Tabs，切分区、目录或新管理请求时重置页签；字体、备份、头像、模板安装和跨页跳转仍使用原有入口。


### 模板安装与移除窗口

`TemplateInstallModal` 和 `TemplateUninstallModal` 使用共享 Dialog 与表单控件，分别由 `useTemplateInstall`、`useTemplateRemoval` 管理请求、校验、加载和错误。GitHub 与 ZIP 输入分别保留模板名，ZIP 支持拖入或文件选择；安装失败保留输入，成功才通知调用方并关闭。命名与模板入口说明可展开查看。安装期间不能重复提交、切换方式或关闭窗口；外部关闭和卸载会使旧操作失效，旧请求不能关闭新窗口或触发旧业务回调。

卸载只展示后端明确许可的模板，确认绑定所选模板 ID；失败保留目标，刷新失败保留已读列表。整包移除的影响说明与内置模板保护保持不变。窗口的 Escape 由当前弹层消费，避免同时关闭后方管理抽屉。字体与原始素材管理、外层分区抽屉仍在迁移，相关旧主题适配按实际引用保留。

模板目录管理同样使用共享选择器和 Dialog。目录列表与渲染能力分别读取，元数据失败不隐藏原始目录；手动模板及缺少渲染入口的目录仍可整组移除，分区根目录只能逐项管理。移除确认固定目录及影响范围，失败保留目标和原因，关闭或卸载后迟到结果不再触发旧业务回调；外部切换目录时，旧删除结果不能清空新选择。

共享 `SearchSelect` 在大量模板场景启用固定 56px 行高的窗口渲染，仅挂载可见选项及少量缓冲。搜索匹配名称、目录和描述；组合框支持方向键、Home、End、Enter 与 Escape，维护选项总数、位置和活动项关系，关闭后恢复触发入口焦点。普通群聊选择保留自然换行布局。选择窗口消费自己的 Escape，避免同时关闭后方管理抽屉。

### 增量会话与旧数据接管

通用身份由 `domain/value_objects/group_session.py` 的 `GroupSession` 表达，字段为真实平台实例 ID 和原始群标识。名称不再限定增量模式。实例精确匹配优先；协议别名只有一个候选时才可使用，多候选明确拒绝，不能通过注册顺序选择机器人。

任务资源锁按“任务类型＋会话”原子预占，省略实例的群级保护与所有该群会话冲突，供旧共享记录和无法确认归属的快照管理使用。分析锁覆盖消息处理、LLM 和分析产物保存；外层渲染及发送仍由活跃任务记录展示。命令、工具和 WebUI 同时检查会话的完整普通分析状态，避免渲染期间误提示空闲；漫画等独立任务类型不因此合并。取消仍按任务 ID 或宿主会话停止标记定位，全局 LLM 信号量保持原有上限。

新历史存档按真实会话显式保存，每次保存独立版本，分别维护会话每日最新、分钟定位及任务索引。版本含平台、群号、日期、任务 ID 与精确创建时间，修订不允许改变归属。删除最新版本只修复该会话指针；指定任务的恢复和重绘不回退到其他任务或无归属旧快照。旧历史保持原样；缺少可确认的平台或源任务时保留查看下载能力，并提示重新选择明确会话，不自动认领或拼接产物。

批次仓储另用同会话短锁保护索引读改写、分页与完整批次读取，避免最终汇总期间的新增或清理产生半份快照。该锁不覆盖 LLM 请求，不把不同实例或不同分析类型全局串行化。这些锁为单个插件进程内协调，不等同于跨进程事务。

WebUI 新任务与续跑共用短暂的受理锁，在登记前重新检查会话状态，覆盖读取请求、保存 Trace 期间的并发提交；后台执行不持有受理锁。续跑复制快照也必须先取得分析锁，拒绝的任务不写入新快照。正文、详情和单点删除在提供任务 ID 时都只匹配该任务及群号、日期，不回退到旧群级记录。LLM 排队取消会恢复临时追踪字段，并且只释放本请求实际取得的并发槽位。

增量群聊目录保留 `groups` 字符串数组，`group_details` 中每条记录包含 `platform_id`、`group_id`、`group_name`。同群号在不同平台显示为不同选项；分析、汇总、状态命令、过期清理、分页详情、删除重置和业务记录导入编辑均使用同一会话仓储。前端请求竞态、跨页选择及确认框也以平台和群号共同定位。平台实例标识沿用 BotManager 的实际实例 ID，不能用适配器类型替代。

旧键没有平台字段，按升级前未发生群号碰撞的约定处理：目录优先归属最近一次有记录的平台，没有历史的记录暂以“平台未记录”保留，首次实际平台分析时接管。完整复制批次和游标后才提交归属标记；原始键保留，迁移失败可重试。归属后禁止未指定平台的旧入口继续修改，后续新平台不会再复制这份旧数据，重置后也不会从备份复活。历史已混合的数据无法自动拆分；注册与接管使用进程内锁，未宣称 AstrBot KV 提供跨进程事务保证。


### 字体与素材的提示和传输状态

字体配置区和字体管理使用共享表单、提示、分页与 Dialog，不依赖 Ant Design。字体列表每页 15 条，按模板、名称或格式筛选时回到首页，缺少记录、真实零值与未安装状态分别处理；筛选后保留完整元数据，翻页支持跨页选择。移除确认固定文件名及 revision，失败保留目标和原因；打开时聚焦取消，关闭返回原入口。替换与预设上传保留原有分块传输、取消和自动命名，未知自定义 CDN 在选择器内原样显示。

独立开发工具箱使用共享 Dialog 和表单控件，悬浮入口位于业务弹窗之下。通信模式切换同步更新 URL 的 `devMode` 与本地缓存；代理模式禁用示例 SSE 注入。手动事件与定时心跳均更新已有示例任务及其关联日志，不创建无法查询详情的任务。关闭工具箱后焦点返回入口；宿主环境不显示工具箱，构建门禁继续禁止生产包包含开发工具与 Mock 模块。

配置中的模板选择使用共享可搜索选择器，按后端真实能力过滤模板；不兼容的已有值保留并提示，不自动覆盖。画廊采用响应式单列到三列布局，缩略图有明确预览入口，安装卸载继续复用原有功能模型。`entities/report/model/useTemplatePreview` 管理自定义图片读取及迟到结果，内置示例仍跟随已选 CDN；视图不直接请求图片 API。共享图片预览保留缩放、旋转、镜像、图库切换及原始尺寸阅读，实际挂载后测量并观察容器；长图在查看区内滚动，关闭子预览后画廊与原入口焦点保留。

字体说明中的旧「数据管理 → 存储分区明细与管理」对应「数据 → 存储空间概览」；「管理 / 上传字体」入口保持不变。默认突出安装状态和操作，手动安装、格式区别及许可信息放入可展开说明，字体内部族名称与文件名的区别仍在列表下方保留。

字体服务器下载、分块上传和浏览器下载的进度使用共享 `Progress`，以实际文件数或已接收字节计算，未知总量不声明百分比。来源、耗时、无数据等待、Raw 回退、失败清单与取消行为保留；浏览器保存只表示保存到电脑，界面继续明确需要上传才能安装到插件。共享提示使用语义颜色、文字和图标，不只靠颜色区分状态。地址与文件名的复制保留失败提示及迟到反馈保护。

原始素材管理使用同一套提示、进度和表单控件，CDN 预设与手填地址均可用，只影响本次下载。清单路径决定上传目标，重新选择同一文件仍可触发替换。批次完成只有实际保存过文件且当前视图仍挂载时才通知管理页刷新，地址校验失败不再触发刷新并清掉错误提示。三路并发、取消与缺失项重试继续由原 ViewModel 负责。
