# WebUI 视觉与交互规范

本文用于插件正式 WebUI 的组件与页面开发。配套分层和通信约束见 [WEBUI_ARCHITECTURE.md](WEBUI_ARCHITECTURE.md)，检查及提交要求见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

正式界面采用 shadcn/ui 和 Tailwind CSS。迁移期间部分旧页面仍使用 Ant Design；它们是待迁移实现，不是新页面的设计基准。

## 视觉方向

浅色使用温润底色、亮黄绿色强调色；深色以中性黑灰为主。强调色用于主要操作、选中项和焦点，不给每个指标分配一种颜色。

界面应轻松、清晰，服务于查看群聊任务和排查问题。保留业务信息，通过层级和按需展开降低阅读负担；不以隐藏功能或缩小文字换取整齐。

- 使用平整表面，减少卡片套卡片和重复边框。
- 不加入装饰性渐变、发光、背景纹理和大面积阴影。
- 不添加标语、无意义的英文标签或重复说明。
- 正常结果使用克制的中性色；错误和需要注意的情况同时提供文字或图标，不能只靠颜色。
- 界面图标统一使用 Tabler 线性图标；用户内容中的表情和群名正常保留。

## 主题与字体

颜色和圆角的唯一实现来源是 dashboard/src/app/styles.css，组件使用语义变量映射的 Tailwind 类，避免各页复制颜色值。

| 用途 | 约定 |
| --- | --- |
| 页面与容器 | bg-background、bg-card、bg-muted |
| 正文与次要文字 | text-foreground、text-muted-foreground |
| 主要操作与选中背景 | bg-primary、bg-accent |
| 错误与破坏性操作 | text-destructive、bg-destructive |
| 边框与焦点 | border-border、border-input、ring-ring |
| 圆角 | 沿用基础组件；通常 12px，弹层可用 16px |

正文使用本地霞鹜文楷屏幕阅读版，保留许可与按字符分片的字体资源，不依赖外部字体服务。日志、代码、地址、标识符和精确数值使用 font-mono。字体资源和许可位于 dashboard/public/fonts，构建后随插件页面发布。

页面标题通常为 22px，区域标题为 16–18px，正文和表单为 14–16px，日志及紧凑元数据为 12px；不使用小于 11px 的文字。常规与强调字重使用 400、500。长内容允许换行，不把重要信息全部截断后依赖悬停查看。

## 基础组件与边界

基础组件直接从 shared/ui 使用，由项目维护 shadcn 组件源码与统一样式。业务页面不直接散布 Radix 原语，也不再为基础组件增加一层仅转发参数的包装。

按当前需求添加组件；图表、编辑器等专用实现可以保留。视图负责布局和交互，查询、操作结果与生命周期由 ViewModel、实体 API 和共享通信层处理。

- 按钮有明确动词，纯图标按钮有可访问名称。
- 输入有可见标签，错误说明关联对应输入。
- 可展开内容有箭头和展开状态，可点击记录提供明确入口。
- 加载、空数据、错误、禁用和确认状态都要设计。
- 操作失败保留输入与已取得的数据，不用成功提示掩盖失败。
- 弹层使用现有 Dialog 的焦点管理，关闭后返回触发入口；多层弹窗保持合理的 React 嵌套关系。

## 页面信息优先级

- 总览首先展示并行任务与需要关注的问题，明确群聊、平台、当前阶段和可用操作。统计及趋势保留，优先级低于正在发生的事情。
- 分析记录提供完整筛选、排序、分页与详情入口。宽表可以在容器内横向滚动，不能撑宽页面；窄屏优先考虑可读的记录排列和直接操作入口。
- 任务详情保留阶段树和选中记录。失败、恢复与当前阶段优先，正常记录可展开；重试、渲染轮次、提示词、日志、产物和原始记录可查。
- 配置与数据管理围绕用户操作组织，说明只解释需要选择什么、限制是什么、失败后如何处理。
- 日志优先保证连续阅读和复制，时间、级别、位置与关联任务保留；实时到达不能强制把用户拉回顶部。

阶段耗时占比明确区分“占任务”与“占父阶段”。父子和并行时间不重复相加；未知耗时不显示成零，占比不表示完成进度。未记录结果不能推断成成功。

## 导航、动效与无障碍

导航文字保持稳定，不叠加 View Transition 新旧页面截图。动效用于选中背景、内容进入和展开等状态变化，不能延迟操作、持续晃动诊断信息或阻止用户输入。

- 通常采用短暂、平滑的过渡；不添加装饰性的弹跳和抖动。
- 尊重 prefers-reduced-motion，关闭非必要动画。
- 快速连续切页以最后一次操作为准，旧回调不能覆盖新状态。
- 往返保留合理的筛选、编辑值、滚动和焦点。
- 支持键盘操作、明显焦点和 Esc 关闭弹窗。
- 页面与 Portal 弹层均响应宿主主题，不只检查独立浏览器主题。
- 窄屏避免页面级横向溢出，主要操作的触控区域不应过小。

## 验证方式

正式入口的 ?devMode=mock 与宿主使用同一套页面、组件和 ViewModel，仅替换通信及数据。示例需要覆盖多任务、长内容、失败、取消、重试和缺失记录，并保持任务、日志与产物关联一致。

组件或页面变动后检查明暗主题、窄屏、键盘、弹层和快速切页。动效需要实际操作验证，静态截图不代替交互测试。Mock 验证不代替真实 AstrBot 的 Bridge、主题和 SSE 验证。

生产构建排除 Mock 与开发工具；旧设计预览仅供迁移参考，正式迁移完成后移除其入口、脚本和重复资源。
